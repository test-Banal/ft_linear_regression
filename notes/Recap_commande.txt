============================================================
PYTHON / UV — AIDE-MÉMOIRE
============================================================


------------------------------------------------------------
1. LANCER UN PROGRAMME PYTHON
------------------------------------------------------------

uv run python fichier.py

Exemple :
uv run python src/mon_projet/main.py


------------------------------------------------------------
2. QUALITÉ DU CODE
------------------------------------------------------------

RUFF — projets DATA / perso / Kaggle

Vérifier :
    uv run --group data ruff check .

Corriger automatiquement ce que Ruff peut corriger :
    uv run --group data ruff check --fix .

Formatter :
    uv run --group data ruff format .


FLAKE8 — projets SCHOOL / 42

Vérifier :
    uv run --group school flake8 .


MYPY — vérification des types

    uv run mypy src


PYTEST — tests

    uv run pytest


Couverture des tests (DATA) :

    uv run --group data pytest --cov=src


------------------------------------------------------------

------------------------------------------------------------
4. UV — À QUOI SERVENT LES FICHIERS ?
------------------------------------------------------------

pyproject.toml
    Configuration du projet :
    - nom
    - version
    - dépendances
    - groupes school/data
    - configuration Ruff/MyPy/Pytest

uv.lock
    Versions EXACTES résolues des dépendances.
    À conserver et à mettre dans Git.

.venv/
    Environnement Python local du projet.
    NE PAS mettre dans Git.

.python-version
    Version Python utilisée par uv.

__init__.py
    Permet notamment d'identifier un répertoire comme
    faisant partie d'un package Python.

------------------------------------------------------------

Structure détaillée sans caches :

    uv tree --depth 1

Dépendances SCHOOL :
    uv tree --depth 1 --group school

Dépendances DATA :
    uv tree --depth 1 --group data

    uv pip list

============================================================
8. WORKFLOW AVANT UN COMMIT — DATA
============================================================

Normalement pre-commit contrôle automatiquement Ruff
lors du commit.

Mais je peux vérifier manuellement :

    uv run --group data ruff check .
    uv run --group data ruff format .
    uv run mypy src
    uv run pytest

Puis :

    git status
    git add .
    git commit -m "message"


IMPORTANT :
    ruff check --fix .

peut MODIFIER les fichiers.

Donc regarder ensuite :

    git diff


============================================================
9. GITHUB — PREMIÈRE CONNEXION D'UN PROJET
============================================================

Vérifier la branche :

    git branch --show-current

Si nécessaire :

    git branch -M main


Vérifier l'état :

    git status


Premier commit si nécessaire :

    git add .
    git commit -m "Initial commit"


Créer ensuite un repository VIDE sur GitHub.

Ne pas demander à GitHub de créer :
    README
    .gitignore
    licence

si ces fichiers existent déjà localement.


Vérifier SSH si besoin :

    ssh -T git@github.com


Vérifier les remotes :

    git remote -v


Ajouter GitHub :

    git remote add origin git@github.com:test-banal/NOM_PROJET.git


Vérifier :

    git remote -v


Premier push :

    git push -u origin main


Après le premier push, les suivants deviennent simplement :

    git add .
    git commit -m "message"
    git push
